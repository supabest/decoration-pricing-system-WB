## 1. 目标与边界（用户已确认）

| 项 | 结论 |

| 目标 | **结果与报表等价**：同一份 BOQ，WB 出的子目编号、综合单价、合价、Excel 与线上一致 |

### 口径查证（证据优于声称）

远端内部模式代码含 `mgmt/profit` 项，但 `globalMgmtRate = 0`、`globalProfitRate = 0`（默认 0，手填才生效）；17% / 12% 只在集团模式从 `group_pricing_rules` 读取且不可手填。
→ **用户「对内不含管理费与利润」的判断与线上默认口径一致**，WB 版不需改动。

## 4. 下一步 = P0「计价内核对齐」

按 TDD 拆成 4 个任务，**每个先写测试、看到红、再写实现**：

| # | 任务 | 交付 | 验收 |
|---|---|---|---|
| P0-0 | 扩快照 + 数据加载层 | `snapshot.py` 支持多数据集 | 测试能读出四类数据集条数；缺密钥时返回空且不报错 |
| P0-1 | `--overrides` 主材价 / 损耗率 / 系数 | 按行号覆盖 `mat_price, waste_rate, coef, conv` | 单测：给价后 `综合单价 = 人工 + 主材×(1+损耗) + 辅材`，与手算逐项一致 |
| P0-2 | 多子目组合 | 一行挂 N 个子目，各自系数换算 | 单测：两子目叠加 = 各自贡献之和 |
| P0-3 | 辅材规则 FIXED / RATE / DETAIL | `price.py` 完整实现 | 单测：三类规则各一组，与远端 `computeAuxForSub` 口径一致 |
| P0-4 | 导出 16 列（+1 WB 扩展列）+ 3 预设 | `export_xlsx.py` 列配置 | 单测：预设列名/顺序/数值列与 `EXP_COLS` 定义一致 |

> 更正：远端 `EXP_COLS` 实测 **16 列**（v1 初稿写 17 是笔误）。WB 另加 1 列「套用子目」用于编号跨班组重复时溯源，默认共 17 列。

### 总验收（硬指标）

1. **67 项现有测试全绿**（不得回归）
2. 同一份真实清单，WB 与线上导出逐行比对：
   - 子目编号一致率 **≥ 90%**
   - 口径一致时**综合单价误差 = 0**
   - 合价 = 综合单价 × 工程量，逐行复核
3. 产出物：一份带完整费用构成的报价表 + 待确认清单（未匹配行、名称与特征矛盾行）

> 验收需用户提供**一份线上导出的同清单报价表**作为基准（只在本机比对、不外发）。若暂无，退化为「公式逐项单测 + 与远端 JS 函数逐行对照」。
