# 系统设计 · WorkBuddy 平台自动套价（最终架构 v1.0）

> 状态：**架构定稿**（2026-11-15）。本文是后续实现的唯一基线，不再讨论「是否做网页工具」「数据放本地还是云端」「同事要不要各自连 Supabase」。
> 适用：多人协作的 WorkBuddy 项目「装修套价」。
> 保密：本文不含任何基准价明细、单价、合价、汇总金额、密钥、令牌或凭据值。

---

## 0. 定死项（来自架构决策，不得再改）

| 层 | 落点 |
|---|---|
| 基准价 / 主材 / 辅材规则 | 用户自己的 Supabase 账号，**云端唯一一份** |
| 数据库身份 | Supabase 里一个**专用只读账号**（普通登录用户，只给价表相关表 SELECT；不是 service_role，不绕 RLS，可随时撤销） |
| 授权 | 项目配置里做**一次公共授权**，凭据由平台云端代持；不给 AI、不落本地、不进对话 / 仓库 |
| 同事 | 只需是 WorkBuddy 项目成员 —— **不用 Supabase 账号、不用看到任何凭据** |
| 技能 | **项目 Skill**（云端统一管理，双端可用，项目配置优先展示） |
| 清单 / 报价 / 成本分析产物 | **项目资产**（云端 5GB，成员共享，可注入任务上下文） |

**一句话架构**：WorkBuddy 项目负责交互、模型判子目、脚本计价与成本分析；Supabase 负责存价；平台公共授权负责把两者连起来。**没有网页前端，也没有独立运算后端。**

## 1. 目标与非目标

### 1.1 目标

1. 在 WorkBuddy 会话里完成工程量清单 **自动套价**：模型判断「该套哪个子目」，确定性脚本完成召回、计价、导出。
2. 综合单价 = **人工费 + 辅材费 + 主材费**，三项都要有真实数据来源，缺价必须显式标注，**禁止静默按 0 计算**。
3. 基准价、主材价、辅材规则、损耗率**只存在 Supabase 云端**，运行时在线拉取，进程内消费。
4. 支持**成本分析**：三费构成与占比、按班组 / 分部汇总、单方造价、与合同额 / 目标成本 / 目标利润率对比、异常行清单。
5. **多人协作**：全项目共用一份数据与一份技能，成员无需配置数据库账号，产物云端共享。

### 1.2 非目标（明确不做）

| 不做 | 原因 |
|---|---|
| 网页工具（`frontend/`、`docs/tool.html`、Cloudflare Pages 页面） | 会话即前端，用户明确「不是做网面工具」 |
| Render / FastAPI 作为运算后端 | 确定性计价与成本分析由项目 Skill 脚本完成；且该后端持有 `service_role`，会绕 RLS、扩大机密面 |
| 集团 296 条对甲报价（管理费 17% / 利润 12%） | 口径不同，二期。对内口径**不加**管理费与利润 |
| 供应商报价导入、公司模板导出 | 需用户提供样例，属后续阶段 |
| 把价表复制到别的库 / 别的云盘 | 导出机密即扩大泄露面；价表只在用户 Supabase 唯一一份 |

### 2.1 各层职责与边界

| # | 组件 | 职责 | 明确边界 |
|---|---|---|---|
| 1 | WorkBuddy 会话 | 接收清单、提问、呈现结论 | 不展示逐条定价明细，只给汇总与异常清单 |
| 2 | 项目 Skill | 技能定义 + 主链脚本 + 旁路脚本 | 云端统一分发；代码入 `dev`，**数据不随包走** |
| 3 | 会话模型 | 读无价候选，判定子目编号 / 班组 / 置信度 | **不接触任何价格**；不负责算术 |
| 4 | 确定性脚本 | 召回、三费计价、导出、成本分析 | 唯一算价处；结果可复算、可测试 |
| 5 | `datasource.py` | 统一取数：云端 REST / 可选离线兜底 | 价表只在内存；失败**明确报错**，不静默用旧价 |
| 6 | Supabase | 存价、按 RLS 授权 | 不存清单、不存报价结果、不存凭据明文 |
| 7 | 项目资产 | 清单输入、报价表、成本分析、审计记录 | 云端共享；不生成本地 xlsx 作为交付物 |

### 2.2 明确移除的组件

| 组件 | 处置 | 说明 |
|---|---|---|
| Cloudflare Pages 网页页面 | **不参与新链路** | 本项目不改动或下线原远端部署 |
| Pages 的 `/sb` 反代 | **临时数据通道** | 只是 `rest/v1` + `auth/v1` 转发，不是网页应用；云端直连验证通过即可去掉依赖，见 §8 |
| Render / FastAPI | **不参与新链路** | 其 `service_role` 绕 RLS，与保密设计冲突 |
| 本地加密快照 | **降级为可选离线兜底** | 不再是主路径；云端失败默认报错，仅调试时 `WB_PRICING_FALLBACK=1` 才回退 |

## 3. 身份与授权设计（核心）

### 3.1 为什么是公共授权

腾讯云《项目》定义：连接器分**公共授权**（管理员统一授权一次，项目成员共享同一账号 / 凭据，平台云端维护，协作任务中可用，调用日志仅管理员可见）与**个人授权**（凭据仅存成员本地、不上传云端，**协作任务中不可用**）。原文：「多人协作任务仅支持公共授权连接器」。

实测：项目级 `automation_list_connectors` 返回 supabase `auth_mode: personal` —— 这正是**需要改成公共授权**的那一项。会话级插件列表看不到 supabase 属正常（个人插件视图），公共授权在项目配置里。

### 3.2 专用只读账号

| 项 | 设计 |
|---|---|
| 类型 | Supabase Auth 普通用户（`authenticated`），**不是** `service_role`，**不是** `anon` |
| 用途 | 唯一被项目公共授权代持的数据库身份，全项目共用 |
| 权限 | 只对价表相关表有 `SELECT`；无任何 `INSERT` / `UPDATE` / `DELETE` 策略；不设 `is_admin` |
| 口令 / 令牌 | 只在平台公共授权配置处录入一次，**不进仓库、不进文档、不进对话、不进 AI 上下文** |
| 撤销 | Dashboard 删除该用户即可立即全部失效；轮换时重建账号并重新做一次公共授权 |
| 同事 | 不需要 Supabase 账号，不需要看到任何凭据，只需是 WorkBuddy 项目成员 |

### 3.3 RLS 现状与两档策略

**2026-11-15 实证**：既有价表（`benchmark_items`、`group_benchmark_items`、`group_pricing_rules`、`material_prices`、`main_material_catalog`、`main_material_categories`、`main_material_prices`、`auxiliary_rules`、`ai_knowledge`、`ai_pricing_logs`）匿名读取**全部返回空集**，收紧迁移已生效。

但现有策略是 `FOR SELECT TO authenticated USING (true)` —— 意思是**任何 Supabase 登录用户都能读全量价表**，并不等价于「只有专用账号能读」。补正方案见 `sql/wb_readonly_access.sql`：

| 档 | 做法 | 影响 | 触发条件 |
|---|---|---|---|
| **A 档（当前默认）** | 不改策略。专用账号是唯一被平台代持的 authenticated 身份；不建任何写策略、不设管理员标记 | **不影响旧网页应用**（其登录用户仍可读） | 立即生效，配置公共授权即可 |
| **B 档（强隔离）** | 建白名单表 + `is_pricing_reader()` 判定函数，把 12 张价表的 SELECT 策略全部改为 `USING (public.is_pricing_reader())` | 旧网页的普通登录用户将读不到价表；其前端直读 `material_prices` / `main_material_*` 会失效 | **旧网页确认停用后**执行 |

> 已决策：默认 A 档，B 档脚本已备好但**不自动执行**。Supabase 的 `authenticated` 是共享角色，无法按账号做表级 GRANT，所以「只给专用账号读」在行级只能靠 B 档实现；A 档靠「只代持这一个账号 + 无写权限 + 可随时撤销」达成同等运维效果。
>
> 遗留匿名面：`profiles`（含 email / is_admin / is_approved）、`pricing_failures`（含清单原文）匿名可读，与套价无关，B 档脚本附带可选收紧段。

### 3.4 审计

| 层 | 记录内容 | 不记录 |
|---|---|---|
| 平台公共授权调用日志 | 管理员可见的调用审计 | — |
| 应用层 `04_审计/` | WB 成员标识、任务 ID、时间戳、涉及的子目编号、数据源版本 | **金额、单价、合价、任何价表正文** |
| 脚本日志 | 表存在性、行数、字段名、HTTP 状态 | 响应正文、凭据、价格 |

取舍：共享身份后 RLS 仍生效，但隔离粒度从「按人」变为「按项目」——这是「全项目共用一份价表」的必然结果。日后若要分级授权，再叠加应用层权限或回到按人授权。

### 4.1 云端表清单

| 类别 | 表 | 状态 | 用途 |
|---|---|---|---|
| 人工基准价 | `benchmark_items` | ✅ 已在库 | 497 条，`internal_code` + `trade_team` 联合定位 |
| 集团基准价 / 费率 | `group_benchmark_items`、`group_pricing_rules` | ✅ 已在库 | 二期对甲报价，本阶段只读不参与计价 |
| 辅材信息价 | `material_prices` | ✅ 已在库 | 21 条材料名 → 单价 |
| 辅材规则 | `auxiliary_rules` | ✅ 已在库 | FIXED / RATE / GROUP 配方 |
| 主材 | `main_material_catalog`、`main_material_categories`、`main_material_prices` | ✅ 已在库 | **真实主材价来源，尚未建立映射** |
| 知识库 | `ai_knowledge` | ✅ 已在库 | 脱敏提示块来源 |
| 损耗率 | `waste_rates` | ❌ REST 404 | 475 条，`sql/wb_supabase_setup.sql` 补表 |
| 辅材清单项 | `aux_excel_items` | ❌ REST 404 | 497 条，同上 |
| 子目 ↔ 辅材映射 | `benchmark_aux_mapping` | ❌ REST 404 | 497 条，同上 |

> 三张缺失表的唯一现存副本是本地加密快照。补库用 `cli.py sync-seeds`：从密文直接 POST 上云，**不落盘、不打印任何价格**，只回传行数与 HTTP 状态；需要一次性管理员级令牌，用完立即清除。

### 4.2 内存快照契约（`datasource.load_snapshot()`）

结构与 `snapshot.load_snapshot()` 完全一致，调用方无需感知数据源：

```python
{
  "benchmark_items":  [ { internal_code, trade_team, work_type, item_name,
                          spec, unit, unit_price, remark,
                          aux_rule_type, aux_fixed_k, aux_rate_detail,
                          waste_rate } ],
  "waste_rates":      { "<internal_code>": float },
  "material_prices":  { "<材料名>": float },
  "aux_excel_items":  [ { code, name, unit, work_type,
                          rate_mats, rule_type, source_sheet } ],
  "main_material_prices":     [...],   # 原样带入，阶段 2 消费
  "main_material_catalog":    [...],
  "main_material_categories": [...],
  "generated_at":     "supabase-live"
}
```

**字段别名映射**（`datasource._BENCH_ALIASES`）：云端列名与历史快照命名可能不同，取数层逐项回退（如 `unit_price` → `price` / `labor_price` / `labor_cost`）。新增字段必须同时更新映射与 `tests/test_datasource.py`。

### 4.3 主链文件契约

| 文件 | 产出者 | 内容 | 是否含价格 |
|---|---|---|---|
| `candidates.json` | `cli.py prepare` | 每行 top-40 候选：编号 / 名称 / 规格 / 单位 | ❌ **绝对不含** |
| `decisions.json` | 会话模型 | 行号 → `code` / `team` / `confidence` / `remark`，或 `subs[]` 多子目 | ❌ 不含 |
| `overrides.json` | 人工 | 行级 `mat_price` / `waste_rate` / `coef` / `conv` | ⚠️ 可含，仅人工维护 |
| 报价表 / 辅材清单 | `cli.py apply` / `aux` | 远端 16 列 + 「套用子目」扩展列，含合计行 | ✅ 产物，只进项目资产 |
| `consistency.json` | `cli.py check` | 相似组、severity、`auto_fix` 建议 | ❌ 不含 |
| `analysis.json` / `.md` | `cli.py analyze`（阶段 3） | 三费占比、汇总、异常行清单 | ⚠️ 仅汇总，不逐条列价 |

`decisions.json` 中 `team` **必填**：`internal_code` 跨班组重复（如 `YQ-01`）。子目级参数优先于行级 `--overrides`。

## 5. 取数层设计（`scripts/datasource.py`）

| 契约 | 规定 |
|---|---|
| 唯一入口 | `load_snapshot()`；`cli.py` 及所有计价脚本只调它，不再直接调 `snapshot.load_snapshot()` |
| 数据源切换 | `WB_PRICING_SOURCE=supabase`（主路径）/ `snapshot`（离线兜底） |
| 凭据 | 只读环境变量（含常见别名兼容）；**不读文件、不写仓库、不回显** |
| 失败语义 | 云端缺表 / 0 行 / 连接失败 → 抛 `SourceError` 明确报错；**不静默回退旧价**。仅 `WB_PRICING_FALLBACK=1` 允许回退 |
| 缓存 | `lru_cache(maxsize=1)`，一次任务内只拉一次；`clear_cache()` 用于凭据轮换 |
| 分页 | `PAGE_LIMIT=5000`，单表一次取全；超出必须改分页，不可静默截断 |
| 体检 | `probe()` 逐表回状态 / 行数 / 字段名，**永不返回价格数值** |
| 补库 | `sync_seeds()` 需管理员级令牌，只读公共授权账号**无权执行** |

### 环境变量（由项目公共授权 / 运行环境注入）

| 变量 | 用途 |
|---|---|
| `WB_PRICING_SOURCE` | `supabase`（主路径） |
| `WB_SUPABASE_URL` | REST 根地址（直连或反代，见 §8） |
| `WB_SUPABASE_ANON_KEY` | publishable / anon key（`apikey` 头） |
| `WB_SUPABASE_TOKEN` | 公共授权注入的 authenticated JWT |
| `WB_SUPABASE_EMAIL` / `WB_SUPABASE_PASSWORD` | 可选：未注入 JWT 时用专用账号换一次令牌 |
| `WB_PRICING_FALLBACK` | 不设；仅调试设 `1` |
| `WB_SUPABASE_SYNC_TOKEN` | 仅一次性补库，用完清除 |

**以上值一律不写进仓库、不写进文档、不贴进对话。**

## 6. 网络通道设计

实测（2026-11-15）：用户侧直连 `*.supabase.co` 在 SSL 层失败（HTTP 000），**绕开本机代理仍失败**；经同源反代 `/sb` 可达。

| 通道 | `WB_SUPABASE_URL` | 判定 |
|---|---|---|
| WorkBuddy 云端任务直连 | `https://<project>.supabase.co` | **首选**，腾讯云出口未必受家庭宽带干扰。**待实测**：在云端任务跑一次 `python cli.py probe` |
| 同源反代 `/sb` | `https://<pages 域名>/sb` | 当前已验证可达；只是数据转发，不是网页应用 |
| VPN 直连 | 直连地址 | 仅本地调试 |

`WB_SUPABASE_URL` 完全由变量决定，两种通道无需改代码。

> **已决策 + 触发条件**：云端任务 `probe` 直连全表 `ok` 且行数非零 → 去掉反代依赖，Pages 可整体下线；直连不通 → 保留 `/sb` 作为纯数据通道。Pages 属原远端部署，本项目不擅自改动或下线。

## 7. 计价引擎与三费口径（不得改动）

```
人工     = Σ(子目单价 × coef × conv)
主材     = Σ(子目主材价 × (1 + 损耗率/100) × coef × conv)
辅材     = 行辅材费（FIXED / RATE / GROUP 三型 + 信息价）
综合单价 = 人工 + 主材 + 辅材
合价     = 综合单价 × 工程量
```

- 对内**不含**管理费 17% / 利润 12%（集团 296 条对甲报价，二期）。
- 一条清单行可挂多个子目，每个子目只套一个基准价编号。
- 尺寸 / 厚度类判断（如「100*100 线槽」按宽+高=200mm 选档）留给模型，召回只做文本相似度。

### 7.1 主材映射（阶段 2，当前最大缺口）

现状：497 条基准价 `mat_price` **全为 0**，主材三表已在库但未接入 → 主材费实质为 0。

| 步骤 | 设计 |
|---|---|
| 1 | 以 `main_material_catalog` 建立「材料编码 ↔ 名称 / 规格 / 单位 / 分类」索引 |
| 2 | `main_material_prices` 按材料编码 + 有效期 + 供应商取有效价；多条命中按「有效期最近 + 优先级」择一，全部记入溯源 |
| 3 | 建立「子目 ↔ 主材」映射：优先用 `benchmark_aux_mapping` 扩展字段显式指定；无显式映射时按名称 / 规格 / 单位从 catalog 召回候选，交模型确认 |
| 4 | 匹配结果写入内存快照的 `mat_price` / `waste_rate`，**不写回价表** |
| 5 | 缺价行：显式标「主材价待补」，进入成本分析异常清单，**禁止静默按 0 出表** |

验收：真实清单 10/10 行三费可拆分；缺价行 100% 被标注；分项之和与综合单价误差为 0。

## 8. 成本分析设计（阶段 3，新增能力）

### 8.1 模块与命令

| 项 | 规定 |
|---|---|
| 新增脚本 | `scripts/analysis.py` |
| CLI | `cli.py analyze <candidates.json> --decisions <decisions.json> [--contract-amount N] [--target-cost N] [--target-profit-rate N] [--area N] --out <analysis.json> [--md <analysis.md>]` |
| 输入 | 与 `apply` 共用 `candidates` / `decisions` / `--overrides`；复用同一套计价结果，保证与报价表同源 |
| 输出 | 结构化 `analysis.json` + 会话内 markdown 结论；写入项目资产 `03_成本分析/` |

### 8.2 指标集

| 组 | 指标 |
|---|---|
| 三费构成 | 人工 / 主材 / 辅材总额与占比（三项占比合计 = 100%）、合计金额、总工程量、行数 |
| 分组汇总 | 按班组（`trade_team`）、按分部（源 sheet / section）汇总金额与占比 |
| 单方指标 | 单方造价（需 `--area`）、单方人工 / 单方主材 / 单方辅材 |
| 目标对比 | 与合同额对比的毛利额 / 毛利率；与目标成本偏差；与目标利润率差额（仅当传入对应参数） |
| 异常行 | ① 主材缺价 ② 单价离群 ③ 未匹配 / 待判定 ④ 低置信度 ⑤ 损耗率异常 ⑥ 工程量为 0 / 空 ⑦ 零综合单价 |

### 8.3 输出契约

```json
{
  "schema_version": "1.0",
  "source": "supabase-live",
  "totals": { "rows": 0, "qty": 0, "labor": 0, "material": 0,
              "aux": 0, "amount": 0, "shares": {} },
  "by_team": [], "by_section": [],
  "per_unit": {}, "targets": {},
  "exceptions": [ { "row": 0, "code": "", "reason": "" } ]
}
```

**保密约束**：报告只给汇总、占比、异常行（行号 / 子目编号 / 原因），**不逐条罗列单价或合价明细**；`exceptions` 里不出现任何金额。与 `kb` / `check` 一样设 fail-closed 守卫，正则兜底。

验收：三费占比合计 100%；`by_team` / `by_section` 分项求和 = `totals.amount`（误差 0）；缺价行 100% 进入 `exceptions`；输出无逐行价格字段。

## 9. 产物与项目资产规范

### 9.1 目录规范（设计，不自动创建）

```
项目资产根（tdrive，云端 5GB，成员共享）
├── 00_规范/        系统设计、计价口径、版本记录
├── 01_清单输入/    <项目编码>/<YYYYMMDD>_<清单名>.xlsx
├── 02_套价产物/    <项目编码>/<YYYYMMDD>/{报价表, 辅材清单, consistency.json}
├── 03_成本分析/    <项目编码>/<YYYYMMDD>/{analysis.json, analysis.md}
├── 04_审计/        <YYYYMM>/audit.jsonl（成员 / 任务 / 子目编号 / 时间戳，无金额）
└── 99_归档/        已结项目
```

### 9.2 规则

| 项 | 规定 |
|---|---|
| 存放 | 清单、报价表、成本分析一律写项目资产；**不把本地 xlsx 当交付物** |
| 命名 | `<项目编码>/<YYYYMMDD>_<类型>_<版本>`；同日重跑追加 `_v2`，不覆盖 |
| 注入 | 自动化任务 / 会话按需把产物作为上下文注入；注入前确认不含逐条定价明细 |
| 权限 | 项目成员共享；不通过 GitHub collaborator 分发（避免 `main` 历史明文价表随加人外泄） |
| 容量 | 报价表体积可控，成本分析只存结构化 JSON + markdown；归档按期移 `99_归档/` |
| 保密 | 报价表含真实单价与合价，属机密产物；**不进 git、不进对话、不进可分发的文档** |

> 平台规则：项目资产的任何创建 / 上传 / 修改 / 删除都需管理员确认后执行。本文只定规范，不自动创建目录或上传文件。

### 9.3 产物写入契约（阶段 3 实现）

新增 `sink` 抽象，把「导出到文件」与「导出到项目资产」解耦：`apply` / `analyze` 产出内存中的 workbook / dict，由 sink 决定落点。CLI 增加 `--out-asset <资产路径>`；本地 `-o` 仅保留给调试，不作为正式交付路径。

## 11. 保密与审计红线（不可放宽）

1. 企业基准价 497 条、集团基准价 296 条属**机密**：禁止输出定价明细、禁止打包进 skill / zip、禁止发布到公开市场、禁止写入可分发的文档。
2. 价表**运行时经 Supabase REST + 用户 JWT 拉取**，靠 RLS / 白名单把关；**不落盘、不入库（除唯一云端源）、不进 prompt、不进对话、不进仓库**。
3. 模型只判子目，`prepare` 候选 JSON 里绝不能出现 `unit_price` / `price` 字段；`kb` 提示块、`check` 报告、`analysis` 报告都不得出现金额 / 单价。
4. 凭据由平台云端代持：**不给 AI、不给同事、不写文件、不贴对话**；禁止使用 `service_role` 作为日常取数身份。
5. 云端取数失败明确报错，不静默用旧价出表。
6. 汇报只给汇总金额、匹配率、占比与异常清单，不逐条罗列定价。
7. 每次 push 前复核 staged 清单无 `.env` / `.enc` / `*.xlsx` / 明文价表 / `data/seeds/`；**只推 dev，不动 main / 原目录 / Pages**。
