- **日期**: 2026-10-11

## 0. 背景与目标

集团内项目向甲方（建设单位）报价须按集团基准价（ZS02 系列）及四部分计价体系
（分部分项工程费 → 措施项目费 → 其他项目费 → 税金，见 ZS02-T02 汇总表）。
现有系统的 497 条基准价 + 计价公式服务于**对内成本分析**，两者口径不同，
按 CLAUDE.md「对内/对外严格分离」原则，本设计新增**第二计价引擎**，与现有引擎并存、互不污染。

**验收总目标（全打通）**: 同一 BOQ 在「对甲报价」模式下完成
AI 套价（ZS02 候选）→ 询价回填甲供主材价 → 导出 ZS02-T02 单位工程计价汇总表。

## 1. 数据层

### 1.1 新表 `group_benchmark_items`（Supabase）

RLS 与 `benchmark_items` 对齐：SELECT 对 authenticated 开放，写操作需 `is_admin=true`。

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | text PK | `ZS02-A-009` 等，296 条 |
| `discipline` | text | `A` 精装 / `B` 水电 / `C` 拆除 / `D` 措施 |
| `section_name` | text | 分部名（地面装饰工程、墙柱面装饰工程…），汇总归类依据 |
| `name` / `spec` / `unit` | text | 项目名称 / 项目特征（结构化多行）/ 计量单位 |
| `work_type` | text | 工种类型（抹灰镶贴工、电工…） |
| `lab_price` | numeric | A 人工单价；可调（T01 通用规则第 3 条允许合同期调整），默认=基准价 |
| `mats` | jsonb | `[{name, price, unit, consumption}]`；**price=null 即甲供未定价**；一子目可多主材（如 ZS02-A-009 = 瓷砖 + 1:3干硬性水泥砂浆） |
| `aux_cost` | numeric | D 辅材费 |
| `mech_cost` | numeric | E 机械费（现有系统无此概念，新增） |
| `is_owner_supply` | boolean | 从项目特征中【甲供】标记解析 |
| `raw_composite` | numeric | Excel 原综合单价 H，仅作导入校验锚点，不作计价依据 |

| 利润率 | 12%，基数=人工+机械 | 同上 |

| 预算包干费率 | 3%，基数=∑(分部分项人工+机械) | T02 |

## 2. 引擎层（tool.html 报价模式开关）

- 顶栏模式开关：`对内成本`（默认，现状一切不变）↔ `对甲报价·集团基准价`
- 集团模式公式：

```
管理费 F = (A人工 + E机械) × 17%
利润   G = (A人工 + E机械) × 12%
综合单价 H = A + Σ(Bi × Ci) + D + E + F + G        ← 主材「单价×消耗量」口径，损耗已含于 Ci
合价 = H × 工程量
```

- AI 面板 `globalMgmtRate/globalProfitRate` 在集团模式**置灰禁用**；
  `rowUnitPrice()/rowTotal()` 按 `mode` 分支，对内成本面板公式不受影响
- 子目行 `subs` 新增 group 形态字段（`work_type/lab_price/mats/mech_cost`），
  契约向后兼容：`m.html` 本期不做集团报价，字段缺省不影响手机/电脑草稿接力
- 甲供未定价子目：H 显示「待询价」态，不计假值；导出汇总表时**前置校验拦截**，
  要求逐条选择：补齐主材价，或显式移入「三、暂估价」（二选一，不允许静默忽略）

## 3. AI 套价复用（同一链路，切换候选集）

- `POST /api/v1/pricing/single` 请求体新增 `schema: 'internal' | 'group'`（缺省 internal，老调用不受影响）
- `ai_pricing_service` 按 schema 切换候选池（497 库 ↔ group 库）与提示词模板；
  LLM 输出契约（`sub_items` JSON）、`parse_ai_response`、重试/回退逻辑**全部不动**
- 匹配依据：BOQ 行名称+特征 ↔ ZS02 的 name+spec（spec 为结构化编号文本，机器友好）
- 知识库 `ai_knowledge_base.json` 新增 `scope: 'group'` 规则组（T01 专用规则转译：
  结合层厚度按比例调主材含量、楼梯投影面积、灯槽/窗帘盒中心线计量、石膏板平面/立面
  路由等）；internal 匹配不加载 group 规则；双副本同步（docs ↔ frontend/public）

## 4. 询价打通（落点 = 甲供空缺主材价）

- 集团模式下「导入主材询价」的目标变为 group 子目 `mats[i].price == null` 的甲供位
- 品类识别复用现有 `classifyMat/MAT_CAT_KEYWORDS/subCategoryScore`，不另起炉灶
- 落点不变式与内部模式同构：只填空缺；同主材已有价 → `原值未动`；
  单位不一致 → 标红不落价；预览弹窗显示 `空→123.45`
- 回填后 H 自动完成计算，「待询价」标记消除

## 5. 输出层（ZS02-T02 汇总表导出）

新端点 `POST /api/v1/export/group-summary`（openpyxl，复用 ExcelExporter 基建），双 sheet：

1. **清单明细表**：按 ZS02-A/B/C/D 原列结构，单价组成 A~H 全分解
2. **单位工程计价汇总表**（T02 同构）：

```
一 分部分项工程费      = Σ 已套价条目合价（按 A/B/C 及各分部小计列示）
二 措施项目费
  （一）绿安费         = ∑(一.人工+机械) × 13%
       单价措施        = 已套 ZS02-D 条目合价（脚手架/成品保护）
  （二）其他措施费      = 赶工措施费（手工金额）+ 成品保护费（若按 D 套价则并入上行）
三 其他项目费
  暂列金额             = 0（固定注：集团规定不予计取）
  暂估价               = Σ 用户显式移入的待套价/待询价项目
  精装修管理及配合费    = 装修面积 × 参数单价（参数空则该行为必填拦截）
  预算包干费           = ∑(一.人工+机械) × 3%
  合同变更费用/涨幅费   = 手工金额行（预留）
四 税金               = (一+二+三) × 9%
五 总造价             = 一+二+三+四；单方造价 = 五 ÷ 装修面积
```

- 装修面积取项目表单新增字段 `projects.fitout_area`（迁移 SQL 随 P1）
- 全部费率从 `group_pricing_rules` 读取，前端展示可追溯（导出备注列注明参数版本）

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| Excel 合并单元格/续行解析错位 → 数据失真 | 导入审计锚定 296 条 H 值逐一比对，不过不入库 |
| 模式开关污染对内公式 | 沙箱测试双夹具：同数据两模式各自公式不变式 |
| `subs` 契约变更破坏手机/电脑草稿接力 | group 字段全部可选、缺省即旧行为；m_parity 回归把关 |
| 费率参数被误改致报价事故 | 参数面板修改留痕（updated_at/updated_by）；导出备注注明参数版本 |
| doc 条款转译遗漏（涨幅、调整系数） | P1 仅落已明确费率；其余以手工金额行过渡，逐期补齐 |
